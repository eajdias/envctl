## Padrões / Preferências (o que funciona)

- 2026-08-25 ✅ Quando um deploy precisar aplicar migration que o aplicador do projeto não lista (ou sincronizar função SQL), rode o arquivo direto no banco (`psql -c "$(cat migracao.sql)"`) e registre em `schema_migrations` manualmente — depois corrija a lista do aplicador no código (porque o efeito desejado é imediato em produção e o código fica correto para deploys futuros).
- 2026-08-25 ✅ Quando o sync/backfill de mensageria falhar por paginação, reproduza com a função REAL de produção dentro do container (não com mock) e confira o `totalCount` da API contra `COUNT(*)` no banco (porque reprodução fiel + ground truth da API é o único caminho para provar a causa raiz).
- 2026-08-21 ✅ Quando precisar cadastrar/consultar servidores SSH, consulte `~/.config/opencode/extras/ssh_servers.md` (inventário local) ou `ssh-manager server list` — nunca IPs/chaves no código (porque mantém dados privados fora do versionamento).
- 2026-08-21 ✅ Quando precisar criar arquivos temporários de teste para bibliotecas com file handler próprio (`xlsxwriter`, `openpyxl`, `sqlite3`), use `with tempfile.TemporaryDirectory() as tmpdir:` (porque garante limpeza automática cross-platform sem locks no Windows e passa no Ruff `SIM115`).
- 2026-08-21 ✅ Quando rodar type-check no frontend, execute `npm --prefix frontend run type-check` (ou `npm ci` seguido de `npm run type-check`) para utilizar o TypeScript das devDependencies (porque evita downloads espúrios do npm).
- 2026-08-21 ✅ Quando integrar webhooks de mensageria (Chatwoot, WhatsApp, etc.) com IA em orquestradores (n8n), adicione nó de guarda condicional antecipado checando atendente atribuído (`assignee_id != null`) e labels de finalização para short-circuit silencioso (`200 OK`) antes da LLM (porque economiza tokens e impede o bot de responder por cima de humanos).
- 2026-08-21 ✅ Quando alimentar agentes LangChain com histórico conversacional, passe apenas a mensagem limpa consolidada (`text: "={{ $json.message }}"`) como input em vez do dump JSON inteiro com metadados (porque o LangChain grava a entrada na tabela de histórico e metadados poluem o contexto).
- 2026-08-21 ✅ Quando persistir contexto/estado incremental em PostgreSQL (JSONB), use merge não-destrutivo `COALESCE(context_data, '{}'::jsonb) || $2::jsonb` no `ON CONFLICT DO UPDATE` (porque impede que nós de auto-save periódicos apaguem campos detalhados coletados por tools anteriores).
- 2026-08-21 ✅ Quando implementar tools com efeitos colaterais externos (Google Calendar, criação de pedidos, envio de e-mails), estruture protocolo de 2 fases no System Prompt (Fase 1: Propor e solicitar confirmação explícita; Fase 2: Só executar a tool após resposta afirmativa do usuário).
- 2026-08-24 ✅ Quando instalar MCP opcional no opencode, adicione entrada no config ÚNICO `~/.config/opencode/opencode.json` (não existe mais `.jsonc` desde 2026-08-26) com `type: local`, `["npx", "-y", "<pkg>", ...]`, `"timeout": 30000` e `"enabled": false` + rode `npx -y <pkg> --version` antes (pre-warm do cache npm) (porque arquivos de config são mesclados por chave com arrays conflitantes; o timeout default de 5s estoura no primeiro download do npx; disabled por default evita custo de contexto de tools não usadas).
- 2026-08-24 ✅ Quando configurar browser automation MCP nesta máquina, use `--browser chromium` no @playwright/mcp (cache ms-playwright já tem chromium) e deixe o chrome-devtools-mcp baixar Chrome for Testing automaticamente (Google Chrome NÃO está instalado no sistema).
- 2026-08-24 ✅ Quando precisar de LSP de framework/stack específica (ex.: tailwindcss), registre PER-PROJECT no `<projeto>/opencode.json` e não global (porque opencode LSP não tem root_dir/root_markers — inicia por extensão em TODOS os projetos; evidência real: Zed #51469, tailwind LS a 100% CPU em projeto sem Tailwind). Template: `"lsp": {"tailwindcss": {"command": ["tailwindcss-language-server", "--stdio"], "extensions": [".tsx", ".ts", ".css", ".html"]}}`.
- 2026-08-24 ✅ Quando quiser instruções anti-hang de shell não-interativo, use `"instructions": ["https://raw.githubusercontent.com/JRedeker/opencode-shell-strategy/trunk/shell_strategy.md"]` no opencode.json (porque é um arquivo de instruções remoto, não plugin npm).
- 2026-08-26 ✅ Quando o usuário pedir tolerância do DCP, use banda `maxContextLimit: 85%` / `minContextLimit: 75%` em `~/.config/opencode/dcp.jsonc` (preferência atualizada em 2026-08-26; era 75/70 até 2026-08-24).
- 2026-08-26 ✅ Quando sugerir plugins opencode, os instalados e aprovados são APENAS 3: **dcp** (contexto/compressão, config 85/75), **ponytail** (anti over-engineering; comandos `/ponytail lite|full|ultra|off`) e **@prevalentware/opencode-goal-plugin** (goal mode: tools `get_goal`/`set_goal`/`update_goal`, slash `/goal`, sidebar). - 2026-08-24 ✅ Plugins de funcionalidade: **@prevalentware/opencode-goal-plugin** (`/goal <objetivo>` c/ guardas: evidência p/ fechar, budgets, checkpoints; NÃO cria toggle no Tab — é slash command + tools + indicador sidebar). - 2026-08-26 ✅ Quando o shell do OpenCode (Windows) precisar de PowerShell, configure `"shell": "pwsh"` (não caminho fixo) (porque a instalação pode vir do Microsoft Store — `WindowsApps\Microsoft.PowerShell_*` — ou MSI — `Program Files\PowerShell\7`; PATH resolve ambos).
- 2026-08-26 ✅ Quando agentes precisarem de libs globais no Windows, use: Node via `NODE_PATH=%USERPROFILE%\node_modules` (`playwright`, `axios`, `cheerio`, `papaparse`) e Python global (`pyyaml`, `requests`, `openpyxl`, `beautifulsoup4`, `pypdf`, `python-docx`, `lxml`, `sqlite3` stdlib) — SEM venv/node_modules por projeto no Windows; Linux/macOS segue isolado (uv/venv).
